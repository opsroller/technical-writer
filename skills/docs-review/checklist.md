# Docs review checklist

Reference, for reviewers. Companion to `SKILL.md`.

## Every page
- [ ] Opens with one line naming its kind and audience.
- [ ] Holds one kind only.
- [ ] Title follows its kind's pattern.
- [ ] Links to its counterparts of other kinds where they exist.
- [ ] Commands copy and run as shown; expected output shown.
- [ ] Terms match the glossary; link text is descriptive; images have alt text.

## Tutorial
- [ ] States what we will do, not what you will learn.
- [ ] One path, no options; a visible result every step.
- [ ] Explanation limited to a clause plus a link.
- [ ] Ran end to end from a clean start.

## How-to guide
- [ ] Named for a goal; starts by saying what it shows.
- [ ] Actions only; branches for real conditions.
- [ ] Skips what any competent user knows; links to reference for options.

## Reference
- [ ] Describes only: no instructions, opinion or history.
- [ ] Mirrors the product's structure; same format as siblings.
- [ ] Generated parts regenerated; hand-written parts consistent with them.

## Explanation
- [ ] Bounded by a "why" or a topic; reads with "About".
- [ ] Gives context, alternatives and trade-offs; owns its opinions.
- [ ] No step-by-step instructions or option lists.

## The set
- [ ] Landing pages introduce and group; lists over ~7 grouped.
- [ ] No empty sections.
- [ ] Changelog entry for user-visible changes.
